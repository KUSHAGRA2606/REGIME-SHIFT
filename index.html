The Core Problem Statement

In the institutional Global Macro and Multi-Asset space, a static allocation is a liability. This dynamic allocation engine ingests noisy, multi-asset market data, classifies hidden economic states using Hidden Markov Models (HMM), and automatically shifts capital between equities, fixed income, and safe havens.

The True Challenge

Standard backtests often hallucinate alpha by acting on data from the future or ignoring the devastating cost of high turnover. This system is engineered for robust, real-world survival.

  • Rigorous walk-forward validation harness
  • Dynamically mapping optimization objectives to specific regimes
  • Explicitly penalizing transaction friction

Core Concepts & Tech Stack

Concepts Mastered

  • Hidden Markov Models (HMM): Classify unobservable economic states without manual labels.
  • Convex Portfolio Optimization: Efficient frontier allocation using CVXPY.
  • Walk-Forward Validation: Strict temporal train/test splits.
  • Performance Metrics: Sharpe, Sortino, Calmar Ratios.
  • Transaction Friction: Explicitly penalizing turnover.

Tech Stack & Data

Leveraging a modern quantitative finance stack based on Python, focusing heavily on unsupervised state classification and convex optimization.

Python 3.9+ hmmlearn CVXPY NumPy & Pandas SciPy

  • FRED API: Macro indicators (CPI, yields, spreads)

Project Goals

  • Build an HMM Regime Classifier: Ingest asset returns, VIX, and macro proxies to detect hidden market states.
  • Implement Dynamic Constraint Mapping: Shift optimizer objective functions by regime.
  • Build a Walk-Forward Validation Harness: Re-fitting the HMM only on past data to eliminate look-ahead bias.
  • Benchmark Against Static Portfolios: Compare against 60/40 and equal-weight baselines.

System Architecture

The system is cleanly divided into separate modules for data ingestion, regime detection, portfolio optimization, and walk-forward backtesting, simulating a true production environment.

1. src/regime_shift/data.py: Data ingestion from Yahoo Finance and FRED.

2. src/regime_shift/hmm_regime.py: HMM fit/inference and regime labeling.

3. src/regime_shift/optimizer.py: CVXPY allocation objectives and constraints.

4. src/regime_shift/backtest.py: Walk-forward backtest and transaction model.

5. src/regime_shift/metrics.py: Sharpe, Sortino, Calmar, drawdown, turnover.

6. src/regime_shift/report.py: Plot generation and tear sheet export.
