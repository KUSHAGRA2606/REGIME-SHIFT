REGIME-SHIFT

Macro-Aware Tactical Asset Allocation Engine

1. The Core Problem Statement

Standard quantitative strategies and static portfolios (like the classic 60/40) rely heavily on stationary assumptions, working perfectly during prolonged bull runs but failing catastrophically during structural market breaks. In the institutional Global Macro and Multi-Asset space, a static allocation is a liability. The ability to mathematically detect, quantify, and adapt to unobservable economic regime changes is the absolute core of modern portfolio management.


This project bridges the gap between unsupervised machine learning and classical convex portfolio theory. It is a dynamic allocation engine built from scratch that ingests noisy, multi-asset market data, classifies hidden economic states using Hidden Markov Models (HMM), and automatically shifts capital between equities, fixed income, and safe havens.


The true challenge of this project isn't just fitting a statistical model to historical data; it is executing that logic without falling victim to look-ahead bias and portfolio thrashing. Standard backtests often hallucinate alpha by acting on data from the future or ignoring the devastating cost of high turnover. By building a rigorous walk-forward validation harness, dynamically mapping optimization objectives to specific regimes, and explicitly penalizing transaction friction, this system is engineered for robust, real-world survival—demonstrating the exact risk-aware mindset that top-tier hedge funds demand from quantitative researchers.

2. Core Concepts & Tech Stack

The engine leverages a modern quantitative finance stack based on Python, focusing heavily on unsupervised state classification and convex optimization.


Concepts Mastered

  • Hidden Markov Models (HMM) & Viterbi Algorithm: Used to classify unobservable economic states without manual labels.
  • Convex Portfolio Optimization: Efficient frontier allocation using CVXPY.
  • Walk-Forward Validation: Strict temporal train/test splits, eliminating look-ahead bias.
  • Performance Metrics: Sharpe, Sortino, Calmar Ratios.
  • Transaction Friction Modeling: Explicitly penalizing rebalance turnover.

Tech Stack & Data Sources

  • Languages & Libraries: Python 3.9+, hmmlearn, CVXPY, NumPy, Pandas, Matplotlib, SciPy.
  • Data Sources: Yahoo Finance (yfinance) for multi-asset daily returns, FRED API for macro indicators (CPI, yields, spreads), and CBOE VIX historical data.

3. Project Goals

  • Build an HMM Regime Classifier: Ingest asset returns, VIX, and macro proxies to detect hidden market states (Bull, Bear, Crisis) without manual labelling.

  • Implement Dynamic Constraint Mapping: Shift optimizer objective functions by regime: Maximum Sharpe in Bull, Minimum Volatility in Crisis.

  • Build a Walk-Forward Validation Harness: Strict temporal train/test splits, re-fitting the HMM only on past data, eliminating look-ahead bias.

  • Model Transaction Friction Explicitly: Apply 5–10 bps turnover penalty per rebalance; show the model survives transaction costs.

  • Benchmark Against Static Portfolios: Compare against 60/40 and equal-weight baselines across Sharpe, max drawdown, and Calmar ratio.

4. System Architecture & Implementation

The system is cleanly divided into separate modules for data ingestion, regime detection, portfolio optimization, and walk-forward backtesting, simulating a true production environment.

[Core Pipeline Modules]

1. src/regime_shift/data.py: Data ingestion from Yahoo Finance and FRED.
2. src/regime_shift/hmm_regime.py: HMM fit/inference and regime labeling.
3. src/regime_shift/optimizer.py: CVXPY allocation objectives and regime constraints.
4. src/regime_shift/backtest.py: Walk-forward backtest and transaction cost model.
5. src/regime_shift/metrics.py: Calculation of Sharpe, Sortino, Calmar, max drawdown, and turnover.
6. src/regime_shift/report.py: Plot generation and tear sheet export.

5. Deliverables & Outputs

The successful execution of the model results in a comprehensive set of performance and analysis outputs designed for a quantitative research portfolio:


  • Trained HMM Model: Regime labels overlaid on historical price data and documented transition probabilities.

  • Dynamic Allocation Backtester: Rigorous walk-forward validation, annotated regime charts, and equity curve visualizations.

  • Performance Tear Sheet: Detailed metrics analysis vs. static benchmarks.

  • Interactive Pipeline: Jupyter Notebook pipeline covering data ingestion $\rightarrow$ regime detection $\rightarrow$ optimization $\rightarrow$ backtest $\rightarrow$ reporting.
